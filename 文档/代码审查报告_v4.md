**项目名称**: BGM (Bangumi 同步工具)  
**审查日期**: 2024年  
**审查版本**: v3.0  
**审查人**: AI 代码审查

---

## 一、项目概述

### 1.1 项目简介
这是一个 WPS Excel 加载项，用于将 Excel 数据批量同步到 Bangumi（追番网站）的收藏列表。

### 1.2 技术栈
- **前端框架**: 原生 JavaScript (ES6+)
- **构建工具**: Vite 5.3.1
- **WPS API**: wpsjs (WPS JavaScript API)
- **加密**: Web Crypto API (AES-GCM)

### 1.3 项目结构
```

├── main.js              # 主入口模块
├── index.html           # 加载项入口页面
```

## 二、代码结构问题

### 2.1 模块依赖混乱

#### 问题描述
1. **入口文件不一致**: `main.js` 和 `ui/taskpane.html` 中加载模块的顺序不同
2. **循环依赖风险**: `unified.js` 导入 `BGM` 从 `util.js`，可能存在循环依赖

#### `main.js` 模块加载顺序
```javascript
const MODULES = [
    { src: 'js/core/constants.js', type: 'module' },
    { src: 'js/core/crypto.js', type: 'module' },
    { src: 'js/util.js', type: 'module' },
    { src: 'js/syncRecord.js', type: 'module' },
    { src: 'js/bangumi.js', type: 'module' },
    { src: 'js/ribbon.js', type: 'module' },
    { src: 'js/systemdemo.js', type: 'script' }
];
```

#### `ui/taskpane.html` 模块加载顺序
```javascript
import '../js/core/constants.js';
import '../js/core/crypto.js';
import '../js/util.js';
import '../js/syncRecord.js';
import '../js/bangumi.js';
import '../js/ui/dialog.js';      // 额外加载
import '../js/ui/message.js';      // 额外加载
import '../js/ui/preview.js';       // 额外加载
import '../js/ui/handlers.js';      // 额外加载
import '../js/sync/scraping.js';   // 额外加载
import '../js/taskpane.js';
```

#### 优化建议
```
1. 创建统一的模块加载配置
2. 在 unified.js 中避免导入 BGM，改用函数参数传递
3. 使用 Vite 的依赖预处理功能
```

### 2.2 双套对话框系统

#### 问题描述
存在两套独立的对话框系统：

1. **HTML 内嵌对话框** (`ui/taskpane.html` 32-63行)
   ```html
   <div id="inputDialog" class="modal">...</div>
   <div id="confirmDialog" class="modal">...</div>
   <div id="alertDialog" class="modal">...</div>
   ```

2. **JS 动态创建对话框** (`js/ui/dialog.js`)
   - 通过 JavaScript 动态创建对话框元素

#### 问题
- 代码重复
- 样式不一致风险
- 维护困难

#### 优化建议
- 统一使用 JS 动态创建方式
- 删除 HTML 中内嵌的对话框

## 三、代码质量问题

### 3.1 硬编码问题

#### 问题 1: API 密钥硬编码
**位置**: `js/core/constants.js:47-52`
```javascript
export const TOKEN_CONFIG = {
    KEY_BYTES: [
        0x42, 0x47, 0x4D, 0x5F, ...  // 硬编码密钥
    ],
};
```

**风险**: 如果代码泄露，Token 安全将受到威胁

**建议**: 使用 WPS PluginStorage 存储密钥，或使用服务器端存储

#### 问题 2: API 地址硬编码
**位置**: `js/core/constants.js:26`
```javascript
export const BGM_CONFIG = {
    API_BASE: "https://api.bgm.tv",
};
```

**建议**: 改为可配置项

#### 问题 3: 魔法数字
**位置**: 多处
```javascript
const SEQ_COL = 4;  // 硬编码 D 列
Math.min(startRow + 5, 10);  // 魔法数字
```

### 3.2 错误处理不一致

#### 问题描述
- 部分函数使用 `try-catch`，部分直接抛出异常
- 错误日志级别不统一
- 部分错误被静默吞掉

#### 示例
```javascript
// bangumi.js - 捕获异常但只记录日志
} catch (e) {
    bgmLog(LOG_LEVELS.WARN, "findHeaderRow 行扫描失败: " + e.message);
}

// syncRecord.js - 捕获异常继续执行
} catch (e) {
    bgmLog(LOG_LEVELS.WARN, "未找到条目 ID 列");
    return;
}
```

#### 建议
- 统一使用 `unified.js` 中的 `handleError()` 函数
- 定义统一的错误码

### 3.3 变量命名不规范

#### 问题
```javascript
// 缩写不规范
let app = getApp();
let ws = getDataSheet();
let sid = extractSubjectId(url);
let bgmLog = ...;  // 与函数同名

// 中英混合
let lastCol = ws.Range(...).End(XL.TO_LEFT).Column;
let token = loadBgToken();

// 语义不清
let i, j, k;  // 循环变量
let _fetchBgmUserInfo = ...;  // 下划线前缀但未使用
```

#### 建议
- 遵循 ESLint 规范
- 统一命名风格
- 使用有意义的变量名

### 3.4 缺少 TypeScript 类型

#### 问题
- 全部使用 JavaScript，无类型检查
- 函数参数无类型注解
- 返回值类型不确定

#### 建议
- 迁移到 TypeScript
- 或使用 JSDoc 注释添加类型

```javascript
/**
 * @param {Worksheet} ws - Excel 工作表对象
 * @param {number} startRow - 起始行号
 * @returns {number} - 表头行号
 */
function findHeaderRow(ws, startRow) { ... }
```

## 四、安全问题

### 4.1 Token 存储安全

#### 问题
- Token 使用固定密钥加密，密钥硬编码在代码中
- 如果用户 Excel 文件被分享，Token 可能泄露

#### 建议
1. 使用 WPS 安全存储 API
2. 添加 Token 有效期验证
3. 实现 Token 刷新机制

### 4.2 API 请求安全

#### 问题
```javascript
// 无请求超时设置
let xhr = new XMLHttpRequest();
xhr.open("GET", BGM_CONFIG.API_BASE + "/me", true);
```

#### 建议
```javascript
const controller = new AbortController();
const timeoutId = setTimeout(() => controller.abort(), 10000);
xhr.signal = controller.signal;
```

### 4.3 敏感信息日志

#### 问题
```javascript
bgmLog(LOG_LEVELS.INFO, "Token: " + token);  // 可能泄露敏感信息
```

#### 建议
- 禁止在日志中输出敏感信息
- 使用掩码处理

## 五、性能问题

### 5.1 同步操作阻塞

#### 问题
`syncRecord.js` 中的同步操作是同步的，会阻塞 UI

```javascript
function markUploadedItemsInSheet(sheetIndex, collections) {
    for (let row = headerRow + 1; row <= lastRow; row++) {
        // 同步操作，每次循环都操作 Excel
    }
}
```

#### 建议
- 使用异步批量操作
- 添加进度回调
- 考虑使用 Web Worker

### 5.2 重复计算

#### 问题
```javascript
// 多次调用 findHeaderRow
let headerRow = findHeaderRow(ws);
let colMap = getColumnMap(ws, headerRow);
let lastRow = getLastRow(ws);
```

#### 建议
- 缓存计算结果
- 合并多次操作为一次

### 5.3 未使用的导入

```javascript
// ribbon.js - 检查是否有未使用的导入
import { showDialog, sendToTaskpane, showTokenDialog, showUserIdDialog } from './ui/dialog.js';
// showDialog 和 sendToTaskpane 未在文件中使用
```

## 六、向后兼容性问题

### 6.1 window 挂载混乱

#### 问题
几乎每个模块都向 window 对象挂载函数，导致：
- 命名冲突风险
- 难以追踪函数来源
- 内存泄漏风险（无法垃圾回收）

```javascript
// util.js
window.loadBgToken = loadBgToken;

// bangumi.js
window.SyncToBangumi = SyncToBangumi;

// dialog.js
window.showTokenDialog = showTokenDialog;

// ... 还有更多
```

#### 建议
1. 使用 ES6 模块导入
2. 减少 window 挂载
3. 添加命名空间前缀

### 6.2 遗留代码

#### 问题
`crypto.js` 中存在遗留代码，但注释说使用 Web Crypto 实际使用 XOR

```javascript
export function encryptToken(token) {
    // 优先使用 Web Crypto API
    if (typeof crypto !== 'undefined' && crypto.subtle) {
        return encryptTokenLegacy(token);  // 注释说优先，实际用的是遗留
    }
    return encryptTokenLegacy(token);
}
```
