## 三、问题分类汇总

### 🔴 严重问题（高优先级）

#### 1. **代码重复严重**
| 位置 | 问题描述 |
|------|----------|
| `dialog.js` L1-144 | 6种对话框模板 HTML 代码重复 |
| `dialog.js` L146-198 | 事件绑定逻辑重复 |
| `unified.js` L22-126 | Dialog API 与 `util.js` L45-111 功能完全重复 |
| `bangumi.js` L688-709 | `getColumnValueCounts` 与 `getColumnMap` 有重复逻辑 |

**建议**：提取公共组件，减少重复代码。

#### 2. **同步 XHR 阻塞 UI**
```javascript
// bangumi.js L524
xhr.open(method, BGM_CONFIG.API_BASE + endpoint, false);  // ❌ 同步请求
```
- **影响**：大量同步时界面无响应，用户体验差
- **建议**：改用异步 XHR + 进度回调

#### 3. **错误处理不一致**
```javascript
// util.js - 返回 null
export function loadBgToken() { return null; }

// bangumi.js L547 - 返回 {code: 0}
return { code: 0, message: "Error: " + err.message };

// unified.js L246-300 - 抛出自定义 BgmError
throw bgmError;
```
- **影响**：调用方难以统一处理错误
- **建议**：统一使用 `Result<T>` 模式或统一错误类型

#### 4. **Token 安全性风险**
```javascript
// crypto.js L221-231
export function encryptToken(token) {
    if (typeof crypto !== 'undefined' && crypto.subtle) {
        return encryptTokenLegacy(token);  // ❌ 实际未使用 AES
    }
    return encryptTokenLegacy(token);
}
```
- **问题**：注释说使用 AES，实际只用了 XOR 混淆
- **风险**：Token 可被轻易逆向解密
- **建议**：真正实现 Web Crypto API AES-GCM

## 三、架构问题分析

### 1. **模块依赖关系混乱**

```
当前依赖图（简化）：

util.js ← bangumi.js ← ribbon.js
    ↑              ↑
    └── ui/dialog.js ← ui/handlers.js
            ↑
            └── core/unified.js

问题：
- util.js 被所有人依赖，但功能最多
- core/unified.js 与 util.js 功能重叠
- ui/dialog.js 直接依赖 util.js
```

### 2. **BgmError 类重复定义**
```javascript
// util.js L602-611
BGM.BgmError = function(message, code, details) {...}

// unified.js L219-241
export class BgmError extends Error {...}
```
- **问题**：两个不同的 BgmError 类
- **建议**：统一使用 `unified.js` 的 ES6 class 版本

### 3. **window 全局污染**
```javascript
// 大量直接挂载
window.SyncToBangumi = SyncToBangumi;
window.bgmiRequestSync = bgmRequestSync;
window._bgmConfirmCallback = {...};
```
- **问题**：命名冲突风险、内存泄漏风险
- **建议**：使用命名空间对象 `window.BGM = {...}`

### 3. **性能优化**

#### 异步化同步请求
```javascript
// 当前：同步 XHR（阻塞）
xhr.open(method, url, false);

// 建议：异步 + 进度回调
export function bgmRequestAsync(method, endpoint, body, token) {
    return new Promise((resolve, reject) => {
        const xhr = new XMLHttpRequest();
        xhr.open(method, endpoint, true);  // true = async
        xhr.onload = () => resolve({ code: xhr.status, data: xhr.responseText });
        xhr.onerror = () => reject(new Error('Network error'));
        xhr.send(body);
    });
}
```

#### 批量处理优化
```javascript
// 当前：逐个同步
for (let i = headerRow + 1; i <= lastRow; i++) {
    await bgmRequestSync(...);  // 串行
}

// 建议：批量 + 限流
const batchSize = 10;
const delay = 800;  // BGM API 限制

for (let i = 0; i < items.length; i += batchSize) {
    const batch = items.slice(i, i + batchSize);
    await Promise.all(batch.map(item => bgmRequestAsync(item)));
    await sleep(delay);  // 批次间延迟
}
```
