## 一、项目定位

**受众**：仓库维护者；WPS Excel 加载项（BGM 插件）用户；下游插件开发者。

**职责**：

1. 作为 **BGM 插件的数据下发源**，通过 GitHub raw URL 向 WPS Excel 加载项提供 Bangumi 条目数据。
2. 接收上游 `Archive` 项目同步来的、已转换完成的 `data/bangumi.jsonlines` 与本期 `differences/` 差异报告。
3. 保留历史差异报告，支持版本回溯与增量分析。
4. **不承担任何数据处理**：dump 转换、README 数字对齐、git 提交推送全部由 Archive 项目本地完成（流水线步骤⑨⑩⑪）。

**GitHub 仓库**：[awujiana/Bangumi-Archive-Anime-Excel](https://github.com/awujiana/Bangumi-Archive-Anime-Excel)（必须为 public）

**当前模式**：**直接 JSONL 模式**（数据规模 ~8 MB < 100 MB 阈值，无需 Release Asset 模式）

**技术栈**：无（本仓库不含任何脚本、不含 CI；转换逻辑与运行环境均在 Archive 项目侧）

## 二、跨项目关系

本仓库是 **三项目数据链路的中转枢纽**：

```
Bangumi 官方 Archive (周三 05:0x 北京时间出 dump)
        ↓ 每周下载
[1] Archive 项目  ── 处理 dump、生成 Excel 与差异
        │
        │ automation_pipeline.py --type 2（步骤⑨⑩⑪）
        │   ⑨ convert_dump_to_jsonl.py      生成 data/bangumi.jsonlines（表头 + 值数组）
        │   ⑩ sync_to_awujiana.py           同步差异摘要到 awujiana 目录（英文命名）
        │   ⑪ push_anime_data_repository.py 提交并推送本仓库（白名单收窄）
        ↓
[2] Bangumi-Archive-Anime-Excel (本仓库)  ── 纯数据下发仓库（无脚本、无 CI）
        │
        │ GitHub raw CDN（自动透明 gzip，实际传输 ~2.6 MB）
        ↓ 直读 JSONL
[3] Excel 加载项  ── WPS 插件解析 JSONL → 写入 Excel → 同步 Bangumi API
```

| 上游           | 接收内容                                                               | 触发方式                                                                    |
| -------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `Archive` 项目 | `data/bangumi.jsonlines` + `differences/{old}_to_{new}/` + `README.md` | Archive 流水线步骤⑪ 自动执行 `python scripts/push_anime_data_repository.py` |

| 下游           | 提供内容                                                     | 访问方式                                                                                             |
| -------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| `Excel 加载项` | `data/bangumi.jsonlines`（表头+值数组，~8 MB，30836 条记录） | `https://raw.githubusercontent.com/awujiana/Bangumi-Archive-Anime-Excel/main/data/bangumi.jsonlines` |

> ⚠️ **提交范围刻意收窄**：步骤⑪ 只提交 `data/bangumi.jsonlines`、`README.md`、本期 `differences/<old>_to_<new>/`；暂存区一旦出现白名单外的文件即中止，防止误提交本地工作文件（如 `xlsx/`）。

详细跨项目链路见上级目录 [../README.md](../README.md) 与工作区根 [README.md](../../../../README.md)。

## 四、核心机制

### 4.1 数据下发流程（直接 JSONL 模式）

```
插件 ──① 读取──▶ data/bangumi.jsonlines (raw URL)
                   │
                   │ ② 逐行解析 JSONL
                   ▼
            ③ 按 SID 比对本地 Excel 行
                   │
                   │ ④ 增量写入（新增/更新/删除）
                   ▼
            ⑤ 写入 Excel 单元格
```

**插件读取 URL**：

```
https://raw.githubusercontent.com/awujiana/Bangumi-Archive-Anime-Excel/main/data/bangumi.jsonlines
```

**限流与传输量**：未认证 raw URL 读取限 60 次/小时/IP。数据文件为 `.jsonlines` 扩展名，GitHub raw CDN 会透明 gzip 压缩，实际传输约 **2.6 MB**（未压缩 ~8 MB）。如遇限流，等待 1 小时或切换 Release Asset 模式（当前未实现）。

### 4.2 数据生成与下发流程（Archive 本地执行）

> ⚠️ 本仓库**没有 CI**。`.github/workflows/convert.yml` 已于 2026-08-05 删除，
> dump→JSONL 转换改由 Archive 项目本地执行，转换结果直接写入本仓库工作区后再提交推送。

```
Archive 项目：automation_pipeline.py --type 2
              ↓
步骤⑨ convert_dump_to_jsonl.py
  读取 Archive 本地 dump/dump-{date}/type2_subject.jsonlines
  按 PluginRecord 字段映射转换，输出「表头 + 值数组」
              ↓
  写入本仓库 data/bangumi.jsonlines（工作区）
              ↓
步骤⑩ sync_to_awujiana.py
  复制本期差异摘要到本仓库 differences/{old}_to_{new}/
              ↓
步骤⑪ push_anime_data_repository.py
  1. 调用 Archive/scripts/update_badges.py --repo-dir <本仓库>
     对齐 README.md 的记录数 / 文件大小 / 更新日期
  2. git add data/bangumi.jsonlines README.md differences/{old}_to_{new}/
  3. 白名单校验（越界即中止）
  4. git commit -m "wiki Excel-{YYYY.MM.DD}" && git push origin main
              ↓

```

| 触发方式 | 条件                             | 说明                                                                     |
| -------- | -------------------------------- | ------------------------------------------------------------------------ |
| 自动     | 每周跑 Archive 流水线（步骤⑨⑩⑪） | 与 Bangumi 官方 dump 节奏对齐（周三）                                    |
| 手动补推 | 步骤⑪ 失败后单独重试             | `Archive/.venv/Scripts/python.exe scripts/push_anime_data_repository.py` |
| 只预览   | 不想真的推送                     | 加 `--push-dry-run`（打印将执行的 git 命令）                             |

**Commit 格式**：

```

```

作者为 Archive 项目所在机器的 git 用户，**不是** `github-actions[bot]`（已无 Actions）。

### 4.3 字段映射（dump → 插件 JSONL）

dump 文件字段与插件 JSONL 字段不一致，必须按以下规则转换。完整字段映射规则、类型守卫、运行时校验详见 Archive 项目的 [`scripts/convert_dump_to_jsonl.py`](../../../../Archive/scripts/convert_dump_to_jsonl.py) 中的 `PluginRecord` TypedDict 定义（生产端唯一真相：`HEADER_FIELDS = tuple(PluginRecord.__annotations__)`）。

#### 输出字段（25 个，3 类）

**基础字段**（3 个，BGM 插件 `GithubRemoteEntry` 接口）：

| dump 字段          | 插件字段    | 类型   | 转换规则                                                          |
| ------------------ | ----------- | ------ | ----------------------------------------------------------------- |
| `id`               | `sid`       | string | 数字转字符串，如 `8` → `"8"`（主键，必填）                        |
| `name_cn` / `name` | `name`      | string | 优先 `name_cn`；若为空字符串或 None，回退到 `name`；都为空则 `""` |
| （dump 日期）      | `updatedAt` | string | 取 dump 日期，格式 `YYYY-MM-DD`（仅日期，不含时间，节省空间）     |

**dump 顶层扩展**（3 个）：

| dump 字段   | 插件字段    | 类型     | 说明                                              |
| ----------- | ----------- | -------- | ------------------------------------------------- |
| `date`      | `date`      | string   | 开播日期                                          |

#### 不输出字段（已移除以减少冗余和内存占用）

| 字段       | 移除原因                                                                                |
| ---------- | --------------------------------------------------------------------------------------- |
| `url`      | 从 `sid` 构造（`https://bgm.tv/subject/{sid}`），BGM 插件同步时自动构造，输出冗余       |
| `type`     | dump 中恒为 `2`（动画条目类型），BGM 插件默认按 2 处理，输出冗余                        |
| `tags`     | 与 `meta_tags` 语义冗余，BGM 插件仅使用 `meta_tags` 写入「标签/分级」列                 |
| `episode`  | dump 中恒为 `0`（dump 不含观看集数），BGM 插件使用 infobox 的「话数」字段写入「集数」列 |
| `platform` | BGM 插件 `EXTENDED_FIELD_MAP` 已移除该字段映射，输出无意义                              |
| `score`    | dump 的 `score` 为数据源平均分（非用户打分），用户在 Excel「打分」列自行维护            |
| `comment`  | dump 不含个人评论，用户在 Excel「剧透/感言」列自行维护                                  |

> ⚠️ **`type` 字段语义说明**：dump 中 `type:2` 表示 Bangumi 条目类型为「动画」（条目类型）；Excel 加载项调用 Bangumi API 时的 `type` 为「观看状态」（1=想看 2=在看 3=看过 4=搁置 5=抛弃），由用户在 Excel「是否看完」列维护。两者完全无关。自 2026-07-30 起，`data/bangumi.jsonlines` 不再输出 `type` 字段。

### 4.4 JSONL 数据格式示例

数据文件采用「**表头 + 值数组**」两段式：第 1 个非空行是表头（字段名数组），
其后每行是与表头**等长**的**值数组**（仍是合法的 JSON Lines，每行一个合法 JSON）。

```jsonl
["sid","name","updatedAt","date","meta_tags","nsfw","播放结束","动画制作公司","话数","片长","制片国家","语言","类型","导演","音乐","人物设定","机械设定","原作","脚本","分镜","演出","原案","系列构成","在线播放平台","关联的动漫ID"]
["8","Code Geass 反叛的鲁路修R2","2026-09-08","2008-04-06",["机战","TV","日本","原创","战斗"],false,"2008年9月28日","サンライズ、david production、スタジオガッツ；作画协力：GONZO","25","","","","","谷口悟朗","中川幸太郎、黒石ひとみ","木村貴宏","寺岡賢司、沙倉拓実；Knightmare设计：安田朗、中田栄治、阿久津潤一","","","","","故事原案：大河内一楼、谷口悟朗","大河内一楼","","85 | 344 | 793 | 1081 | 3219 | 8813 | 8816 | 8817 | 8819 | 8820 | 17967 | 32214 | 33389 | 35866 | 51042 | 73715 | 78546 | 91493 | 99952 | 102098 | 110909 | 118733 | 118734 | 118735 | 118736 | 118737 | 118738 | 120756 | 120758 | 141050 | 145943 | 188684 | 188685 | 199228 | 199229 | 199230 | 199231 | 231875 | 231982 | 231989 | 237827 | 239861 | 306532 | 309324 | 321523 | 336526 | 377946 | 391213 | 391214 | 391873 | 400807 | 405346 | 452308 | 667009 | 667019"]
```

- 值数组的顺序与长度**严格对应表头**；缺失字段补默认值（字符串 `""`、`meta_tags` `[]`、`nsfw` `false`）。
- 字段名只在表头出现一次，不再随 3 万条记录重复，因此文件体积比「每行一个完整对象」**减半**（16.09 MiB → 7.65 MiB），且完全无损。
- **扩展名必须是 `.jsonlines`**：GitHub raw CDN 是否 gzip 只看扩展名（已实测，与文件大小无关）。`.jsonl` → `application/octet-stream` 不压缩；`.jsonlines` / `.json` / `.md` / `.txt` → 文本并透明压缩。
- 消费端解析约定：**首个非空行必须是纯字符串数组（表头）**，其后每行必须是与表头等长的数组。
- 消费端解析唯一入口：`ts/sync/github-sync-diff.ts` 的 `parseJsonl()`（github / gitlab / gitee / gist / local 五个同步源共用）。
- 更完整的示例（含 2 条记录）见 [github-data-distribution.md](./github-data-distribution.md)。

字段定义详见 [github-data-distribution.md](./github-data-distribution.md)。

## 六、Release Asset 模式（备选，当前未启用）

仅当数据增长到 ≥100 MB 或需要版本历史/不限流下载时启用。本仓库当前数据规模 ~8 MB，**无需此模式**。

切换步骤详见 [项目操作指南.md 第五章](./项目操作指南.md#五release-asset-模式大文件备选)。

### 两种模式对比

| 特性      | 直接 JSONL 模式（当前启用） | Release Asset 模式（预留）   |
| --------- | --------------------------- | ---------------------------- |
| 适用场景  | 小文件（< 100MB）           | 大文件（> 100MB）            |
| path 配置 | `data/bangumi.jsonlines`    | `latest.json`                |
| 数据格式  | 直接 JSONL                  | zip 压缩包（内含 JSONL）     |
| 版本管理  | 无（直接覆盖）              | 有（Release tag 历史）       |
| 下载方式  | raw.githubusercontent.com   | github.com/releases/download |
| 限流      | 60 次/小时（未认证）        | Release 下载不限流           |

> **注意**：当前插件代码仅实现了直接 JSONL 模式。Release Asset 模式（zip 下载+解压）**尚未实现**——需在 `ts/sync/github-sync.ts` 中新增实现（全仓库检索 `browser_download_url` / `releases/download` / `latest.json` / `JSZip` / `DecompressionStream` 均为 0 命中）。

### 7.3 历史数据归档

`differences/` 目录随每期提交累积（当前 49 个文件）。数据文件本身不做历史保留（每次覆盖），需要历史版本时从 git 历史取。

```bash
# 查看某一期的历史版本
git log --oneline -- data/bangumi.jsonlines
git show {commit}:data/bangumi.jsonlines | head -2

# 清理过老的差异目录（注意：这会让步骤⑪ 的白名单指向不存在的目录，需同步 Archive 侧配置）
git rm -r differences/2026-06-01_to_2026-06-08/
git commit -m "chore: archive old differences 2026-06-01_to_2026-06-08"
```

> `xlsx/` 目录为 Archive 侧本地归档工作目录（步骤⑧ 写入、步骤⑤ 读取上期存档），
> **刻意不入库**，不要 `git add`。

### 7.4 回滚

```bash
# 1. 查看提交历史，定位上一版本的 commit
git log --oneline -- data/bangumi.jsonlines

# 2. 回退到指定版本（保留工作区其他改动）
git checkout {previous-commit} -- data/bangumi.jsonlines

# 3. 提交推送
git add data/bangumi.jsonlines
git commit -m "chore: rollback data/bangumi.jsonlines → {previous-commit}"
git push origin main

# 4. 回滚后 README 的徽章/统计会与数据不一致，需重新对齐
cd d:/编程/awujiana/Archive
.venv/Scripts/python.exe scripts/update_badges.py --repo-dir ../Bangumi-Archive-Anime-Excel
```

### 7.6 故障排查

| 现象                         | 可能原因                                                                        | 处理                                                                      |
| ---------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 插件读取 JSONL 404           | 仓库非 public / path 错误 / 分支错误                                            | 检查仓库可见性、branch、path 配置（应为 `data/bangumi.jsonlines`）        |
| 插件报「首行必须是表头」     | 文件仍是旧的「每行一个完整对象」格式                                            | 用 Archive 的 `convert_dump_to_jsonl.py` 重新生成（表头 + 值数组）        |
| 插件报「字段数不匹配」       | 表头字段数与某行值数组长度不一致                                                | 检查是否有手写/截断的行；重新生成文件                                     |
| 插件下载后是乱码             | 扩展名写成了 `.jsonl`（CDN 不压缩、按二进制返回）                               | 改回 `.jsonlines`，CDN 才会按文本透明 gzip                                |
| 限流（60次/小时）            | raw URL 未认证读取                                                              | 等待 1 小时，或切换 Release Asset 模式（当前未实现）                      |
| 步骤⑪ 中止（白名单校验失败） | 暂存区出现 `data/bangumi.jsonlines` / `README.md` / 本期 differences 之外的文件 | 检查数据仓库工作区是否残留本地文件（如 `xlsx/`），清理后重跑              |
| 步骤⑪ 推送失败               | 网络 / 凭据 / 远端有新提交                                                      | 在数据仓库手动 `git pull --rebase` 后重跑 `push_anime_data_repository.py` |
