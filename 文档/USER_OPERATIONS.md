## 命名规范说明

本文档中涉及的核心术语和命名约定如下：

### 术语定义

| 术语                 | 说明                                                                 | 对应代码/路径                                    |
| -------------------- | -------------------------------------------------------------------- | ------------------------------------------------ |
| **Panel**            | 主侧边栏面板（原 Taskpane），提供数据操作入口                        | `ui/panel.html`、`ts/panel/panel-page.ts`        |
| **Settings Panel**   | 设置面板，独立于主 Panel 的配置管理界面                              | `ui/settings.html`、`ts/entry/settings-entry.ts` |
| **panel_id**         | 主 Panel 在 PluginStorage 中存储的唯一标识，用于跨会话持久化面板状态 | PluginStorage key: `panel_id`                    |
| **settings_pane_id** | Settings Panel 在 PluginStorage 中存储的唯一标识                     | PluginStorage key: `settings_pane_id`            |

### 函数名映射（Taskpane → Panel）

为统一命名规范，以下函数名已从 `taskpane` 前缀改为 `panel` 前缀：

| 旧函数名                | 新函数名             | 说明                      |
| ----------------------- | -------------------- | ------------------------- |
| `initTaskpane`          | `initPanel`          | Panel 初始化入口          |
| `startTaskpane`         | `startPanel`         | Panel 启动函数            |
| `refreshTaskpaneUI`     | `refreshPanelUI`     | 刷新 Panel UI             |
| `isTaskpaneContext`     | `isPanelContext`     | 判断是否在 Panel 上下文中 |
| `ensureTaskpaneVisible` | `ensurePanelVisible` | 确保 Panel 可见           |

### 日志前缀

日志输出中的前缀已统一为 `[panel]`，替代原有的 `[taskpane]`。

### 数据兼容

- `panel_id` 替代原 `taskpane_id`，无旧数据兼容需求
- 已存储的旧 `taskpane_id` 键值会在下次启动时被新的 `panel_id` 替代

## 第一章 Ribbon 功能区操作

WPS 菜单栏 →「Bangumi 同步」选项卡 →「Bangumi」分组，共包含 **12 个控件**。

---

### 1.1 打开同步面板（btnShowPanel）

| 属性     | 说明                                           |
| -------- | ---------------------------------------------- |
| **位置** | Ribbon → Bangumi 同步 → Bangumi → 打开同步面板 |
| **功能** | 切换 Panel 侧边栏的显示/隐藏状态               |
| **图标** | `images/panel.svg`                             |

**前置条件：** 无。

**操作步骤：**

1. 点击「打开同步面板」按钮。
2. 若侧边栏当前隐藏，则立即显示；若已显示，则隐藏。
3. 面板显示后，自动加载已保存的全部配置（Token、用户ID、GitHub 配置等）。

**UI 反馈：** 侧边栏立即出现或消失，无弹窗提示。

**边界情况：**

1. **首次安装后首次打开**：面板为空状态，所有配置项显示为「未设置」。
2. **WPS 重新启动后首次打开**：面板从 PluginStorage 读取上次保存的配置，Token、GitHub 配置等自动回填。
3. **面板已处于显示状态再次点击**：面板将被隐藏，下次打开时配置保持不变。

**错误处理：** 若侧边栏创建失败（如 WPS 内部错误），按钮无反应，需重启 WPS。

### 1.2 上传同步（btnSyncBangumi）

| 属性     | 说明                                                  |
| -------- | ----------------------------------------------------- |
| **位置** | Ribbon → Bangumi 同步 → Bangumi → 上传同步            |
| **功能** | 将 Excel 中的观看状态、评分、标签等数据上传到 Bangumi |
| **图标** | `images/sync.svg`                                     |

**前置条件：**

- 已设置 Bangumi Token
- Excel 工作表包含「Bangumi URL」列
- 已锁定目标数据表

**操作步骤：**

1. 点击「上传同步」按钮。
2. 系统自动读取 Token、工作表、列映射等配置。
3. 弹出数据预览确认对话框，显示：总行数、有效条目、已上传（跳过）、待同步、不上传（状态跳过）、无效（无SID）。
4. 显示冲突策略和增量同步设置说明。
5. 点击「是」开始同步，点击「否」取消。
6. 同步过程中 WPS 状态栏显示实时进度 `[当前/总数] 消息`。
7. 同步完成后弹出结果对话框，显示成功/失败/跳过数量。

**UI 反馈：**

- 确认对话框：WPS 原生 MessageBox。
- 进度反馈：WPS 状态栏文本更新。
- 完成提示：WPS 原生 MessageBox 显示统计结果。

**边界情况：**

1. **Token 未设置**：弹出「请先设置 Token」错误提示，同步中止。
2. **工作表未锁定或无数据**：弹出「未找到数据工作表」提示。
3. **缺少 Bangumi URL 列**：弹出「未找到 Bangumi URL 列」提示。
4. **同步进行中重复点击**：弹出「同步正在进行中，请稍后再试」提示，拒绝重入。
5. **网络不通时冲突检测**：冲突检测步骤依赖 Bangumi API，网络异常时该步骤被跳过，同步继续执行。
6. **增量同步开启**：仅同步指纹（名称+状态+评分+标签）发生变化的条目，已上传且无变化的条目自动跳过。

**错误处理：** 同步异常时弹出错误提示，状态恢复为空闲。

### 1.3 仅同步变更（chkIncrementalSync）

| 属性     | 说明                                                 |
| -------- | ---------------------------------------------------- |
| **位置** | Ribbon → Bangumi 同步 → Bangumi → 仅同步变更         |
| **功能** | 切换增量同步模式，仅上传自上次同步以来发生变更的条目 |
| **类型** | 复选框（CheckBox）                                   |

**前置条件：** 无。

**操作步骤：**

1. 勾选：开启增量同步模式，上传同步时仅处理指纹有变化的条目。
2. 取消勾选：关闭增量同步模式，上传同步时处理所有有效条目。

**UI 反馈：**

- 复选框勾选状态立即切换。
- 状态保存到 PluginStorage（`bgm_incremental_sync`）。
- 侧边栏「冲突处理策略」区域的「仅同步变更」复选框通过轮询机制在 2 秒内同步状态。

**边界情况：**

1. **首次使用无同步记录**：增量同步效果等同于全量同步（所有有效条目均视为变更）。
2. **侧边栏同步延迟**：Ribbon 勾选后，侧边栏对应复选框最长 2 秒后同步更新。
3. **PluginStorage 不可用**：勾选状态无法持久化，重启 WPS 后恢复默认（关闭）。

**错误处理：** PluginStorage 异常时日志记录警告，不影响当前会话的内存状态。

### 1.4 跳过冲突（chkSkipConflicts）

| 属性     | 说明                                                    |
| -------- | ------------------------------------------------------- |
| **位置** | Ribbon → Bangumi 同步 → Bangumi → 跳过冲突              |
| **功能** | 设置冲突处理策略为「跳过冲突」，保留 Bangumi 端已有数据 |
| **类型** | 复选框（CheckBox）                                      |

**前置条件：** 无。

**操作步骤：**

1. 勾选：冲突检测时，存在差异的条目将被跳过（SID 加入 skipSids 集合）。
2. 取消勾选（默认）：冲突检测时，使用 Excel 数据覆盖 Bangumi 端。

**UI 反馈：**

- 复选框勾选状态立即切换。
- 状态保存到 PluginStorage（`bgm_skip_conflicts`）。
- 侧边栏「冲突处理策略」下拉框通过轮询机制在 2 秒内同步。

**边界情况：**

1. **冲突检测网络异常**：即使勾选跳过冲突，冲突检测失败时该策略不会生效（不会跳过任何条目）。
2. **侧边栏同步延迟**：Ribbon 勾选后，侧边栏对应下拉框最长 2 秒后同步。
3. **与「仅同步变更」组合使用**：两种策略独立叠加，可同时生效。

**错误处理：** 同 1.3 节。

### 1.5 启用同步记录（chkEnableSyncRecord）

| 属性     | 说明                                           |
| -------- | ---------------------------------------------- |
| **位置** | Ribbon → Bangumi 同步 → Bangumi → 启用同步记录 |
| **功能** | 切换同步记录功能的开启/关闭                    |
| **类型** | 复选框（CheckBox）                             |

**前置条件：** 无。

**操作步骤：**

1. 勾选：开启同步记录，每次操作后在「同步记录」工作表中追加记录。
2. 取消勾选：关闭同步记录，操作不再写入记录表。

**UI 反馈：** 同 1.3 节，状态保存到 PluginStorage（`bgm_enable_sync_record`）。

**边界情况：**

1. **同步记录表不存在**：首次开启后，系统会在执行同步时自动创建记录表。
2. **记录表损坏**：开启状态不影响同步流程，仅记录功能不可用。
3. **侧边栏复选框同步**：通过轮询机制 2 秒内双向同步。

### 1.6 设置Token（btnSetToken）

| 属性     | 说明                                         |
| -------- | -------------------------------------------- |
| **位置** | Ribbon → Bangumi 同步 → Bangumi → 设置Token  |
| **功能** | 打开 WPS 原生输入框设置 Bangumi Access Token |
| **图标** | `images/token.svg`                           |

**前置条件：** 无。

**操作步骤：**

1. 点击「设置Token」按钮。
2. WPS 弹出输入框，默认显示当前已保存的 Token。
3. 粘贴或输入新的 Access Token。
4. 点击「确定」保存；点击「取消」放弃修改。
5. 保存后自动调用「测试Token」流程验证有效性。

**UI 反馈：**

- WPS 原生 InputBox 弹出。
- 保存成功后自动发送测试请求。
- 测试结果通过 WPS MessageBox 显示。

**边界情况：**

1. **用户点击取消**：Token 保持原值不变。
2. **Token 为空字符串**：不保存，弹出「Token 不能为空」提示。
3. **Token 保存失败（PluginStorage 不可用）**：弹出「Token 保存失败，请检查插件存储权限」错误提示。
4. **新 Token 与旧 Token 相同**：仍会清除旧过期信息并重新查询有效期。
5. **测试请求网络超时**：弹出「网络超时，请重试」，但 Token 已保存。

### 1.7 测试Token（btnTestToken）

| 属性     | 说明                                        |
| -------- | ------------------------------------------- |
| **位置** | Ribbon → Bangumi 同步 → Bangumi → 测试Token |
| **功能** | 验证当前 Token 是否有效，并显示用户信息     |
| **图标** | `images/TestToken.svg`                      |

**前置条件：** 已设置 Token。

**操作步骤：**

1. 点击「测试Token」按钮。
2. 系统向 `https://api.bgm.tv/v0/me` 发送 GET 请求。
3. 请求附带 `Authorization: Bearer <token>` 请求头。
4. 等待响应（超时 15 秒）。
5. 根据结果显示不同提示。

**UI 反馈：**

- **成功（HTTP 200）**：弹出「Token 有效！用户：xxx ID：xxx」提示。
- **Token 无效（HTTP 401）**：弹出「Token 无效或已过期，请重新设置」提示。
- **网络错误**：弹出「网络错误，无法连接到 Bangumi API」提示。
- **超时**：弹出「网络超时，请重试」提示。
- **其他 HTTP 错误**：弹出「Token 验证失败 (HTTP xxx)」提示。

**边界情况：**

1. **Token 未设置时点击**：弹出「请先设置 Token！」提示。
2. **响应 JSON 解析失败**：弹出「解析响应失败，请重试」。
3. **被 GFW 墙或断网**：触发网络错误分支，Token 本身可能有效。
4. **用户信息获取成功**：自动保存用户名和用户 ID，侧边栏头像区域更新。

### 1.8 复制Token（btnCopyToken）

| 属性     | 说明                                        |
| -------- | ------------------------------------------- |
| **位置** | Ribbon → Bangumi 同步 → Bangumi → 复制Token |
| **功能** | 将当前 Token 复制到系统剪贴板               |
| **图标** | `images/CopyToken.svg`                      |

**前置条件：** 已设置 Token。

**操作步骤：**

1. 点击「复制Token」按钮。
2. 系统创建临时 textarea 元素，将 Token 写入并执行 `document.execCommand('copy')`。
3. 复制完成后显示结果提示。

**UI 反馈：**

- **成功**：弹出「Token 已复制到剪贴板」提示。
- **Token 未设置**：弹出「未设置 Token，请先设置！」提示。
- **复制失败**：弹出「复制失败，浏览器不支持剪贴板操作」提示。

**边界情况：**

1. **浏览器不支持 execCommand**：降级为手动复制提示。
2. **多次快速点击**：每次均执行完整复制流程，无防抖。
3. **剪贴板权限受限**：在某些安全策略下可能失败。

### 1.9 设置用户ID（btnSetUserId）

### 1.10 打开收藏页（btnOpenCollection）

| 属性     | 说明                                         |
| -------- | -------------------------------------------- |
| **位置** | Ribbon → Bangumi 同步 → Bangumi → 打开收藏页 |
| **功能** | 在浏览器新标签页中打开 Bangumi 用户收藏页面  |

**前置条件：** 已设置用户 ID。

**操作步骤：**

1. 点击「打开收藏页」按钮。

2. **浏览器被阻止弹窗**：需允许 WPS 的弹出窗口权限。
3. **用户 ID 为空**：不会触发，弹出错误提示。

### 1.11 数据同步（btnSyncFromGithub）

| 属性     | 说明                                                                   |
| -------- | ---------------------------------------------------------------------- |
| **位置** | Ribbon → Bangumi 同步 → Bangumi → 数据同步                             |
| **功能** | 触发远程仓库数据下载并合并到 Excel（远程 → Excel，与上传同步方向相反） |
| **图标** | `images/github.svg`                                                    |

**前置条件：**

- 已在侧边栏配置 GitHub/GitLab/Gitee/Gist/本地文件 源
- 配置通过 `isGithubConfigComplete()` 校验

**操作步骤：**

1. 点击「数据同步」按钮。
2. 系统校验 GitHub 配置完整性（owner/repo/path 或 gistId 或本地文件路径）。

4. 写入 PluginStorage 信号（`bgm_request_github_sync` = 当前时间戳）。
5. Panel 轮询检测到信号后，弹出确认对话框。
6. 用户确认后，在 Panel 中执行完整的同步流程（进度弹窗、结果弹窗）。

**UI 反馈：**

- 若配置不完整：弹出「GitHub 仓库配置不完整，请先在面板中设置 owner/repo/path」提示。

- 实际同步进度和结果在 Panel 中展示。

**边界情况：**

1. **Panel 未打开**：系统自动创建并显示 Panel，然后写入信号。
2. **PluginStorage 不可用**：弹出「无法通知任务面板执行同步，请手动在面板中点击「立即同步」」提示。
3. **信号写入延迟**：Panel 轮询间隔 2 秒，最长 2 秒后触发。
4. **配置为本地文件源**：仅需本地文件路径非空即可。
5. **配置为 Gist 源**：仅需 gistId 非空即可。

#### 2.10.5 同步策略（githubStrategy）

| 属性     | 说明                                                                               |
| -------- | ---------------------------------------------------------------------------------- |
| **位置** | Panel → 数据同步 → 同步策略                                                        |
| **元素** | `<select id="githubStrategy">` + `<button data-action="showSyncGuide">❓</button>` |

**策略选项：**

- `add-update` — 新增+更新（不删除）：默认策略，远程有则更新，本地无则新增
- `add-only` — 仅新增（不更新已有）：远程有新条目时新增，不覆盖本地已有数据
- `update-only` — 仅更新（不新增）：本地有则更新，不添加远程新增
- `mirror` — 镜像同步（含删除）：本地完全对齐远程，删除远程已不存在的条目（⚠️ 注意：该策略并非完全镜像远程，要完全一致需先删除本地全部数据后再同步，建议新建工作簿操作）
- `force-overwrite` — 强制覆盖（含空值）：以远程数据完全覆盖本地，包括空值字段

**追加合并规则（适用于所有策略）：**

- 标签/分级：远程标签追加到本地后面，使用 `|` 分隔（已包含值时不重复追加）
- 名称：更新时远程名称追加到「别名」列，保留本地「名称」列不变；新增时直接写入「名称」列
- 制作公司/动画制作公司：远程 `动画制作公司` 字段会同步到本地 `制作公司` 和 `动画制作公司` 两列（双列映射）
- 其他扩展字段：直接以远程值覆盖本地值

**查看详细说明：** 点击策略选择框右侧 `❓` 按钮或选择 `mirror` 策略后的提示区，可打开/关闭使用引导说明。

### 2.x Panel 宽屏布局说明

Panel 侧边栏采用自适应卡片网格布局，卡片宽度在不同面板宽度下保持一致（280-400px），面板变宽时自动增加列数。

#### 推荐面板尺寸

| 面板状态    | 宽度范围   | 卡片列数 | 说明                           |
| ----------- | ---------- | -------- | ------------------------------ |
| 最小停靠    | ≤ 400px    | 1 列     | 紧凑模式，信息密度最高         |
| 常规侧边栏  | 500-800px  | 2 列     | Excel 默认侧边栏宽度，推荐使用 |
| 宽屏停靠    | 800-1200px | 3 列     | 多卡片同时可见                 |
| 浮动/最大化 | ≥ 1200px   | 4+ 列    | 充分利用宽屏空间               |

#### 调整面板宽度的方法

1. **拖拽分隔条**：Excel 侧边栏与主窗口之间的分隔条可左右拖拽调整宽度
2. **双击 Ribbon 按钮**：再次点击功能区的面板按钮可切换停靠/浮动模式
3. **拖动面板标题栏**：按住面板顶部标题栏拖拽到屏幕边缘可停靠，拖离边缘可变为浮动窗口

#### 宽屏模式下的操作建议

- **浮动面板 + 最大化**：在多显示器环境下，将 Panel 拖至副显示器并最大化，可同时查看 4+ 个操作卡片
- **滚动条说明**：卡片内的数据预览表格支持独立滚动（横向/纵向），不影响面板整体布局
- **自适应重排**：调整面板宽度后卡片自动重新排列，无需刷新页面

- 仓库所有者（owner）
- 仓库名（repo）
- 分支名（branch）
- JSONL 文件路径（path）

Panel 底部的「📖 使用引导」区域提供快速入门说明：

- **基础步骤**（始终可见）：4 步简明指引 — 设置 Token → 确认必填列 → 选择工作表 → 执行操作
- **详细操作**（点击「📖 显示详细操作」展开）：
  - **Token 设置**：创建/更新/有效期说明
  - **数据同步**：远程仓库 → 本地 Excel 的完整流程
  - **上传同步**：本地 Excel → Bangumi 的完整流程
  - **收藏下载**：Bangumi → 本地 Excel 标记流程
  - **预览与验证**：放大预览、详情查看、同步记录
  - **⚠️ 注意事项**：镜像同步说明、制作公司映射等

### 5.3 同步策略引导

在 Panel → 数据同步 → 同步策略区域，点击右侧 `❓` 按钮可打开同步策略详细说明：

- 显示当前所选策略的描述
- 列出通用规则（新增/更新/制作公司映射等）
- 提供完全镜像的重要提醒

### 5.4 日常使用流程

#### 流程 A：上传同步（Excel → Bangumi）

```
准备阶段：
  1. 确保 Token 已设置（Ribbon「测试Token」验证）
  2. 确保工作表已锁定
  3. 可选：设置冲突策略和增量同步

执行阶段：
  4. Ribbon「上传同步」或 Panel「📤 上传同步」
  5. 查看数据预览统计，确认条目数量
  6. 确认开始同步
  7. 进度弹窗显示实时进度（可暂停/停止）
  8. 完成后查看统计结果
```

#### 流程 B：收藏下载（Bangumi → Excel 标记）

```
准备阶段：
  1. Token 已设置
  2. 工作表已锁定
  3. 收藏下载固定使用 Bangumi API（需 Token）

执行阶段：
  4. Panel「📥 收藏下载」
  5. 系统检测工作表是否为空
     - 若为空：弹出确认，从 Bangumi 账号收藏列表自动填充条目
     - 若表头缺失：先自动写入标准表头
     - 写入 Bangumi URL、名称、别名、类别、是否看完、打分、标签、感言等列
  6. 确认执行回写
  7. 系统拉取收藏列表 → 匹配 Excel 行 → 标记颜色
  8. 进度弹窗显示两阶段进度
  9. 完成后查看匹配数量
```

#### 流程 C：数据同步（远程仓库 → Excel）

```
准备阶段：
  1. 配置同步源（GitHub/GitLab/Gitee/本地/Gist）
  2. 可通过「🔌 测试」验证连接性
  3. 选择同步策略
  4. 可选：设置时间筛选

执行阶段：
  5. Ribbon「数据同步」或 Panel「⬇️ 立即同步」
  6. 确认同步配置
  7. 下载远程数据 → 按策略合并到 Excel
  8. 进度弹窗显示下载和合并进度
  9. 完成后查看新增/更新/删除统计

回滚阶段：
  10. 如需撤销：点击「↩️ 撤销上次同步」
```

#### 流程 D：预览与单条上传

```
准备阶段：
  1. 点击 Panel「👁️ 预览同步」

执行阶段：
  2. 系统生成卡片式预览（包含所有可见行）
  3. 通过状态筛选下拉框过滤
  4. 点击单张卡片的「上传」按钮进行单条上传
     或点击「全部同步」执行批量上传
  5. 上传结果实时反映在卡片状态上
```

### 5.7 故障排查速查

| 问题                                    | 可能原因               | 解决方案                        |
| --------------------------------------- | ---------------------- | ------------------------------- |
| 同步时提示「请先设置 Token」            | Token 未设置或已清除   | 重新在 Token 设置区输入         |
| 上传时提示「未找到 Bangumi URL 列」     | Excel 缺少必需列       | 添加「Bangumi URL」列并填入链接 |
| 数据同步时提示「GitHub 仓库配置不完整」 | owner/repo/path 未填写 | 在数据同步区填写完整的仓库地址  |
| Token 测试时提示「网络错误」            | 被 GFW 墙或断网        | 检查网络连接，必要时使用代理    |
| 上传同步时提示「同步正在进行中」        | 防重入保护             | 等待当前同步完成后再操作        |
| 预览数据未加载                          | 未先刷新数据           | 点击「🔄 刷新数据」重新加载     |
| 撤销同步时提示「没有可撤销的操作」      | undoStack 为空         | 先执行一次数据同步操作          |
| 复制 Token 失败                         | 浏览器不支持剪贴板     | 手动选择 Token 文本 Ctrl+C 复制 |
