## 1. 需求

1. 用户可在设置页切换界面语言，**立即生效**，不用重启 WPS。
2. 语言包与主包解耦：可单独打包、单独下载、单独更新。
3. 安装途径三条：
   - **内置**：随 zip 一起发布，开箱即用；
   - **下载**：设置页点一下就拉取并落盘；
   - **拖入**：把 `locales/<code>/` 目录拖进加载项目录即可被识别。
4. 第一批支持 **简体（源语言）/ 繁体 / 英语**。

## 3. 关键技术问题：不重启切 ribbon（**已实测，结论有变**）

### 3.1 实测结论（2026-11-01，WPS 12.1.0.29158）

| 控件         | `getLabel` 是否被调用 | `Invalidate()` 后是否重调 | 结论               |
| ------------ | --------------------- | ------------------------- | ------------------ |
| `<tab>`      | ✅ 首次渲染即调用     | ✅ 会重调（实测 #1 → #2） | **可运行时切换**   |
| `<group>`    | ❌ 从未调用           | —                         | 只能用静态 `label` |
| `<button>`   | ❌ 从未调用           | —                         | 只能用静态 `label` |
| `<checkBox>` | ❌ 从未调用           | —                         | 只能用静态 `label` |

补充实测：

- 把 button 的静态 `label` 删掉、只留 `getLabel`，仍然不调用 → 不是「静态值优先」，是**没实现**。
- `InvalidateControl('buttonOpenSyncPanel')` 调用成功（不抛错），但同样不触发 `getLabel`。
- `getVisible` / `getScreentip` 在 button 级也从未被调用（同一轮探测）。
- button 级已确认可用的动态属性只有 `getImage` 与 `getPressed`（项目既有实证）。

### 3.2 为什么二进制证据会误导

`kshell.dll` 里确实存在 `\0getLabel\0` 等属性名字符串，但**属性名存在 ≠ 每种控件都实现了动态取值**。WPS 只给 `<tab>` 接了这条路径。

教训：二进制只能证明「解析器认识这个属性」，证明不了「所有控件都走动态取值」——必须真机跑。

### 3.3 方案调整

**tab 名：运行时切换**（`getLabel` + `ribbonUI.Invalidate()`）
**group / button / checkBox：改写 `ribbon.xml`，下次启动 WPS 生效**

落地步骤：

1. 25 个 `label` 抽成语言资源（`locales/<code>/ribbon.json`），与主语言包同批维护。
2. 切语言时：
   - tab 名 → `Invalidate()` 即时变；
   - 其余 24 个 → 用 FSO 重写加载项目录下的 `ribbon.xml`，toast 提示「Ribbon 按钮文案将在下次启动 WPS 后切换」。
3. 重写规则：**只替换 `label` 属性值**，控件结构、`id`、`onAction`、`getImage`、缩进一字不动；写前存 `.bak`，写完重新解析一次确认 XML 合法，失败则回滚。
4. 加载项目录可写（`%APPDATA%\kingsoft\wps\jsaddons\`），不需要管理员权限。

### 3.4 副作用与代价

| 项       | 说明                                                                                                                              |
| -------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 用户感知 | tab 名立刻变、按钮文案要重启。设置页必须明写，否则会被当成 bug                                                                    |
| 版本升级 | `publish.mjs` 覆盖安装会把 `ribbon.xml` 换回源语言 → 每次升级后要按当前语言重写一次（放在首次打开面板或 `ribbon-entry` 初始化时） |
| 回滚     | 写坏 `ribbon.xml` = ribbon 整个不显示。必须 `.bak` + 解析校验                                                                     |

### 3.5 附带发现：`OnAddinLoad` 在启动后 10 秒内从未被调用

探针记录里没有任何 `ONLOAD called`，`window.__ribbonUI` 始终为 `null`；而 `Application.ribbonUI` 与 `wps.ribbonUI` 都可用（`Invalidate` 可调）。

影响：`ts/ribbon.ts` 的 `OnAddinLoad` 里那些初始化（`app.ribbonUI = ribbonUI`、`app.Enum = WPS_ENUM`、`PluginStorage` 的 `EnableFlag` / `ApiEventFlag`、`initializeWorkbookAutoDetection()`）在真机上**没有执行**。

`app.ribbonUI` 之所以还能用，是因为 WPS 自己就把 `ribbonUI` 挂在了 `Application` 上，不是我们赋的。

> 这条超出 i18n 范围，但应单独立项排查：工作簿自动检测是否因此失效。

## 4. 架构设计

### 4.1 语言包格式

```
locales/
├── zh-CN/
│   └── locale.js      # 源语言，随包内置
├── zh-TW/
│   └── locale.js
└── en/
    └── locale.js
```

```js
// locales/en/locale.js —— ESM 模块，内容仍是纯数据（不含逻辑）
export default {
  schemaVersion: 1,
  code: 'en',
  name: 'English',
  nativeName: 'English',
  version: '2.4.0',
  updatedAt: '2026-11-01',
  messages: {
    'ribbon.tab': 'Bangumi',
    'ribbon.buttonOpenSyncPanel': 'Open Sync Panel',
    'settings.appearance.title': 'Appearance & Navigation',
    'common.itemsCount': '{count} items',
  },
}
```

> **为什么是 `.js` 不是 `.json`**（2026-11-01 真机实测，见 `真机验证手册.md` §7.3）：
> 安装态任务窗格跑在 `file://` 下，`fetch` 读本地 `.json` 直接 `Failed to fetch`；
> 而 `<script type="module">` 一直可用（整个插件都靠它跑）。所以语言包走
> **ESM `import()`** 这条已被证明的通道，不新增任何本地读取能力。
> 改回 JSON 会让安装态静默退回硬编码中文，而 dev（http）模式完全正常——验不出来。

- **key 命名**：`<域>.<组件>.<语义>`，尾段 camelCase；域取 `ribbon` / `panel` / `settings` / `clean` / `enrich` / `highlight` / `cf` / `donate` / `common` / `error`。
- **变量占位符**：`{name}` 形式，译文必须保留同名占位符（门禁校验）。
- **不翻译**：日志正文、`console.*`、代码注释、数据字段名。用户可见的 toast / 弹窗 / 按钮 / 表头必须翻。

### 4.2 运行时（新模块 `ts/i18n/`）

```
ts/i18n/
├── index.ts        # 对外 barrel：t / setLocale / getLocale / applyI18n
├── locale-store.ts # 加载、缓存、回退、覆盖率统计
├── translate.ts    # t() 与占位符替换
└── dom.ts          # data-i18n 扫描与替换
```

核心接口：

```ts
export type LocaleCode = 'zh-CN' | 'zh-TW' | 'en'

export function t(key: string, vars?: Record<string, string | number>): string
export function getLocale(): LocaleCode
export async function setLocale(code: LocaleCode): Promise<void>
export function applyI18n(root: ParentNode = document): void
export function onLocaleChange(listener: (code: LocaleCode) => void): () => void
export function getLocaleCoverage(code: LocaleCode): { translated: number; total: number }
```

**回退链**：当前语言 → `zh-CN` → 返回 key 本身（并在 `console.warn` 一次，避免刷屏）。

**覆盖率**：加载语言包时与 `zh-CN` 的 key 集合求差，设置页显示「English · 已翻译 82%」。

### 4.3 静态 HTML

```html
<h3 data-i18n="settings.appearance.title">🎨 外观与导航</h3>
<input data-i18n-placeholder="settings.token.placeholder" placeholder="粘贴 Token" />
<button data-i18n-title="common.refresh" title="刷新">↻</button>
```

- `data-i18n` → `textContent`（保留子元素时用 `data-i18n-html`，需过 `sanitizeHtml`）
- `data-i18n-placeholder` / `-title` / `-aria-label` / `-value` → 对应属性
- 页面加载后跑一次 `applyI18n()`；切语言时再跑一次

### 4.4 动态文案

```ts
// 之前
toast(`已关闭 ${closed} 个工具页面`, 'success')
// 之后
toast(t('panel.closeAll.done', { count: closed }), 'success')
```

### 4.5 ribbon

- `<tab>`：补 `getLabel="GetRibbonLabel"`，回调返回 `t('ribbon.tab')`，切语言后 `Invalidate()` 即时生效
- group / button / checkBox：**不加 `getLabel`**（实测无效），改为按语言重写 `ribbon.xml`（见 §3.3）
- `ts/ribbon.ts`：新增 `GetRibbonLabel` 挂到 `window`（WPS 只能调 window 上的函数）；`startRibbonConfigPolling` 加 `lastLanguage`，变化时 `ribbonUI.Invalidate()`（**全量**，不是 `InvalidateControl`）
- 重写 XML 的模块单独放 `ts/tools/ribbon-xml-writer.ts`：读模板 → 只替换 `label` 值 → 解析校验 → 备份 → 写盘，失败回滚

### 4.6 跨窗格同步

```
设置页 setLocale('en')
  → setConfig(CONFIG_KEYS.LANGUAGE, 'en')
  → PluginStorage
      ├─ 各任务窗格 subscribeConfigPoll([LANGUAGE]) → applyI18n() + 重渲染动态区
      └─ ribbon 侧 2s 轮询 → ribbonUI.Invalidate() → 重调 GetRibbonLabel
```

延迟 ≤2 秒，无需重启。**不要**试图用 `postMessage` 跨窗格广播（项目已多处踩坑，见 `ts/tools/theme.ts` / `nav-order.ts` 注释）。

### 4.7 安装途径（✅ 2026-11-01 落地，实现细节见 §P4）

| 途径 | 实现                                                                                                                        | 备注                               |
| ---- | --------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| 内置 | 构建时把 `locales/zh-CN`、`zh-TW`、`en` 打进 zip                                                                            | 三个语言包合计 111 KB（实测）      |
| 下载 | `fetch` raw CDN 的 `locales/<code>/locale.js` → `verifyAssetIntegrity` → FSO 写盘到 `<加载项目录>/locales/<code>/locale.js` | **不用 zip**，单文件即可，避开解压 |
| 拖入 | 用户把 `locales/<code>/` 目录拖进加载项目录                                                                                 | 设置页「打开语言包目录」+ 重开页面 |

下载源：`raw.githubusercontent.com/awujiana/My-Bangumi-Database-for-WPS/main/locales/<code>/locale.js`。

- 分支是 **`main`** 而不是原计划的 `publish`：项目里更新包（`version.json` / zip）与数据同步
  全部走 `main`，语言包没有理由单独一条分支。
- **不做 Release 资产兜底**。语言包单文件 36 KB，raw CDN 挂了 Release 也不会好；真拿不到时
  用户还有「打开语言包目录」手动放入这条路，多一条降级链只增加没被验证过的代码。
- 语言包**不进 Release 资产**，直接放仓库 `locales/` 目录 —— 可增量更新，不必每次发版。

> ⚠️ 这里的 URL 与 `ts/tools/update-check.ts` 的 `UPDATE_OWNER` / `UPDATE_REPO` 共用常量，
> 换仓库时两处一起动。

### 4.9 英语的特殊处理

- 术语：番组/番剧 → `anime`；同步 → `sync`；富化 → `enrich`；条件格式 → `conditional formatting`；数据清理 → `data cleanup`；分片 → `shard`；收藏 → `collection`。
- **长度**：英文普遍比中文长 30–50%，ribbon 按钮与表格列宽会溢出。必须用真浏览器探针复测（`npm run check:shard-layout` / `npm run audit:layout`），必要时给按钮文案加短版（`ribbon.buttonOpenSyncPanel.short`）。

### 4.10 增量迁移策略（关键）

**允许半翻译**：未迁移的文案保持简体中文显示，不阻塞发布。设置页显示覆盖率，达到 95% 才在语言列表里标「完整支持」。

迁移顺序（按用户触达频率）：

1. ribbon（25 条）—— 每次打开 WPS 都看见
2. 设置页 + 主面板（sync-panel.html + settings.html，~550 段）
3. toast / 错误消息 / 弹窗（`ts/ui/message.ts`、`dialog.ts`、`action-handlers.ts`）
4. 条件格式页（289 处，单文件最大）
5. 富化 / 清理 / 高亮 / 赞赏页
6. 日志与排障文案（**不翻**，或只翻错误消息）

**实际结果与三处偏离计划**：

1. **清单是 `locales/index.js`，不是 `locales/index.json`。** 与语言包同一个理由：安装态页面
   跑在 `file://` 下，`fetch` 读本地文件被 CEF 拦死（`Failed to fetch`，2026-11-01 真机实测），
   只有 `import()` 能读。清单随包发布、必须能被本地读到，所以只能是 ESM。
   在线那份走 `fetch`（`https://` 不受此限），两条通道各读各的。
2. **落盘前必须把内容转成纯 ASCII，这是本轮最大的一脚坑。** 写盘唯一通道是 FSO 的
   `CreateTextFile(path, isOverwrite, isUnicode)`，它只能写 **UTF-16 LE（带 BOM）** 或
   **系统 ANSI**，**写不了 UTF-8** —— 而 `.js` 模块必须是 UTF-8，否则中文全是乱码、
   `import()` 直接语法错误。绕法：把非 ASCII 字符全部转成 `\uXXXX`（`toAsciiModule`）。
   转义后仍是合法 JS，而 **ASCII 在 ANSI 代码页与 UTF-8 下逐字节相同**，编码问题就此消失。
   配套加了 `isAsciiRoundTripSafe`：转义后重新解析，`JSON.stringify` 必须与原来逐字相同，
   不过就放弃写入 —— 转义写错会让用户装上一个坏包，而界面只会退回中文，看不出是安装器干的。
3. **没有「刷新语言列表」按钮。** 语言集合由 `LocaleCode` 这个字面量联合类型固定
   （`'zh-CN' | 'zh-TW' | 'en'`），扫描 `locales/*/locale.js` 也变不出第 4 种语言；
   门禁规则 ⑦ 还要求语言按钮与 `LOCALE_CODES` 严格一一对应（顺序也一致），动态加语言
   必须连门禁一起改。所以 P4 的范围定为**「更新 / 修复内置语言包」**，安装机制本身写成
   code 无关（清单里的 `code` 过 `isLocaleCode` 白名单），将来放开只改 UI 与门禁。
   手动拖入的文件在**重开页面**后生效（ESM 按 URL 缓存模块，热替换没有可靠办法）。

**哈希必须对 LF 归一。** 工作区 `core.autocrlf=true`（检出 CRLF、提交 LF），发布出去是 LF。
直接哈希工作区字节会算出一个**永远对不上发布端**的值 —— 下载校验 100% 失败，且报错只说
「SHA-256 不一致」。`gen-locale-index.mjs` 与门禁都先 `replaceAll('\r\n', '\n')` 再算。

**本批踩到并已固化的经验（累计 17 条）**

1. **key 存在 ≠ 已接线**：`enrich.lock.*` 九个 key 早就在语言包里，`enrich-lock.ts` 却仍写死中文，
   `check:i18n` 也不会报（它只校验「HTML/代码引用的 key 存在」，不校验「key 有没有被用」）。
   收尾必须反向扫一遍：把 `ts/` 里所有 `t()`/`tOr()` 的第一参抽出来比对语言包，**同时**看界面文案是否还写死。
2. **`tOr` 的兜底原文也是模板**，必须走 `interpolate(fallback, variables)`，否则英文下露出 `{count}`。
3. **改文案要 bump `updatedAt`**：在线安装的「要不要更新」判据是 `version` + `updatedAt`，不看哈希
   （见 `locale-manifest.ts` 文件头）。只加 key 不 bump，已装用户永远收不到新包。
4. **`t`/`tOr` 从 `../i18n/locale-store.js` 直连**，别从 `i18n/index.ts` 桶取：桶会连带
   `locale-install` → `tools/save-file` → `ts/index`，后者模块顶层写 `window`，node 环境的单测直接
   `ReferenceError: window is not defined`。
5. **正则 `[^\`]*` 抓模板串会在嵌套反引号处截断**：`已导入 ${n} 条规则${skipped > 0 ? \`（…）\` : ''}`这类「模板串里套模板串」的写法，提取脚本只拿到前半段，替换后源码残留半截模板。
**判据**：替换脚本必须断言「替换后该行不含裸反引号 / 能通过`tsc`」；发现残渣就整段手写替换。
6. **`eslint --fix` 会删掉它认为「没用到」的 `// eslint-disable-next-line`**：
   `prefer-blob-reading-methods` 那行被 `--fix` 连同说明一起删除，留下 3 个空格的行。
   **改完必须重跑 `npx eslint <文件>` 确认 0 error**，别只看 `--fix` 的退出码。
7. **`{x: x}` 会被 `object-shorthand` 判错**：脚本批量生成变量对象时统一写成 `{ x }`。
8. **常量表会在模块加载那一刻把译文定死**：语言包是**异步**加载的，`const LABELS = {…}` /
   `const TEXT = '…'` 一旦在模块顶层求值，`tOr` 拿到的永远是兜底原文。
   **判据**：凡是要展示给用户的字符串常量，一律写成 `function xxx(): string { return tOr(...) }`。
   本批 `PROGRESS_TEMPLATE` / `CLUSTER_MODE_LABELS` / `MERGE_MODE_LABELS` / `EMPTY_HINT_*` 全是这个改法。
9. **门禁的贪婪正则会把「同形状的兄弟对象」一起吞进来**：`check-nav-order.mjs` 的
   `export const PAGE_MODULES\b[^{]*\{([\s\S]*)\n\}` 取的是**最后一个** `\n}`，新增的
   `PAGE_LABEL_KEYS` 里同样有 `  'x': [` 形状的页面条目 → 被当成页面块解析、`ids` 覆盖成空数组
   → 报「`<main>` 内未定位到任何模块」。**改成惰性 `([\s\S]*?)\n\}`**（对象内部没有零缩进的 `}`）。
   教训：给「靠正则读源码」的门禁新增兄弟常量时，先跑一遍门禁。
10. **模块名与导航项必须是同一份文案**：`NavModule` 加 `labelKey` 复用 `<page>.nav.*`，
    41 个 key **由脚本按「页面命名空间 + 中文值」反查生成**（反查不到或命中多个即报错），
    手写 41 处必然抄错；单测再兜一层「每个模块都带 `.nav.` key」。
11. **`t()` 的未知 key 告警不能无条件发**：`warnOnce` 走 `bgmLog` → `tools/util` → `logger`，
    而不少单测把 `logger` 整个 mock 掉 → 一条 `tOr` 就报
    `No "logger" export is defined on the mock`。判据加一条：**源语言没加载时不告警**
    （那种状态下每个 key 都「未知」，告警没有信息量；单测正跑在这个状态）。
12. **同一个字面量在一处出现两次时，`sub()` 的期望次数要写 2**：`恢复默认失败` 在
    `shortcuts-settings.ts` 里出现两次，脚本先写 `times=1` 直接报「实际 2 处」；
    拆成两次 `times=1` 又会在第一次替换后把第二处也吃掉。**先 `grep -c` 数清楚再写**。
13. **繁体特例要「生成后改 JSON」**：`apply-batch2.py` 只吃 `(key, zh, en)` 三元组，
    遇到 OpenCC 转错的词（`改绑` → `改綁`）不要在表里塞第四列，而是生成后改
    `patch-batch.json` 再写入 —— 加第四列会让解包直接崩。
14. **把常量表改成 getter 表，比重写成函数省 39 行改动**：`_T` 有 39 处调用点，
    改成 `T.set()` 就要动 39 行；改成 `get set(): string { return tOr(...) }` 后
    **调用点一个都不用改**，语义也正确（访问那一刻才求值，切语言立即生效）。
    例外是带占位符的条目 —— 它必须收参数，所以 `tokenExpiringSoon` / `tokenExpiringCritical`
    直接内联进 `token.ts` 写成 `tOr(..., { remaining })`，顺手把 `{}` 换成具名 `{remaining}`。
15. **先扫死条目再动手翻**：`_T` 的 65 个条目只有 28 个被引用，37 个是历史残留
    （连接测试弹窗 / 头像加载 / Token 续约都已迁到别的模块）。翻这 37 个 = 往三份语言包里
    塞 111 条永远没人看的噪声。判据：`grep -rn "_T\.\w*" ts/ tests/` 取并集与条目表求差。
16. **测试里写 `_T.xxx` 当期望值，会跟着实现一起变**：`tests/token.test.ts` 原来的
    `_T.tokenExpiringCritical.split('{}').join('2 天')` 在条目被删后直接变成
    `no-unsafe-member-access`（`_T` 上没这个属性 → error type）。改成断言最终字符串
    `'Token 即将过期（2 天），请尽快重新获取！'` 反而更硬 —— 它验的是「占位符真的被填了」，
    而不是「函数调了同一个表」。
17. **多行模板串改成数组 `join('\n')` 再翻**：同步确认弹窗原本是一整段带 12 空格缩进的
    模板串，整段当一个 key 翻，译文里会带上一堆无意义缩进。拆成
    `previewLines` 数组 + `join('\n')` 后，每行一个 key，英文下也不会出现「缩进对不齐」。
    这类改动测试通常没断言正文（`confirmAsync` 只被 mock 掉），改前 `grep` 一遍确认。
