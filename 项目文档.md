## 一、项目定位

**受众**：BGM 加载项开发者；WPS 加载项发布者；终端用户（动画收藏管理者）。

**职责**：

1. 作为 WPS Excel 加载项，向用户提供 Bangumi 番剧收藏管理能力。
2. 从远程同步源（GitHub / GitLab / Gitee / Gist / 本地文件）拉取 Bangumi 条目数据，按 SID 增量写入 Excel。
3. 调用 Bangumi API（OAuth 2.0）将本地 Excel 编辑的收藏状态、评分、标签、评论同步回 Bangumi 服务端。
4. 提供暂停/恢复/停止、进度弹窗、冲突解决、URL 自动补全、同步记录工作表等增强能力。

**技术栈**：

- 语言：TypeScript 6（严格模式，0 处 `any`，203+ 处 `unknown` 配合类型守卫）
- 宿主：WPS ET（表格）加载项，通过 `wpsjs` 开发框架
- 测试：Vitest 4 + jsdom 29
- 构建：Vite 6 + `vite-plugin-static-copy`
- 依赖：`zod` 4（运行时校验）、`dompurify` 3（XSS 防御）
- 代码规范：ESLint 8 + Prettier 3 + Husky 9 + lint-staged 16

**强制规范**：本项目代码需符合《微信小程序前端架构设计规范 v2.0》的 🔴 强制等级要求（类型安全、异步可控、数据可信、资源零泄漏、性能优体验）。当前已通过 [MULTI_DIMENSION_AUDIT_2026_06_27.md](./文档/MULTI_DIMENSION_AUDIT_2026_06_27.md) 8 维度审查基线。

## 二、跨项目关系

本加载项是 **三项目数据链路的最下游消费者**：

```
Bangumi 官方 Archive (周三凌晨 dump)
        ↓ 每周下载
[1] Archive 项目  ── 处理 dump、生成 Excel 与差异
        │
        │ scripts/sync_to_awujiana.py + convert_dump_to_jsonl.py
        ↓ 复制差异摘要 + 生成 data/bangumi.jsonl
[2] Bangumi-Archive-Anime-Excel  ── 数据下发仓库（GitHub 同步仓库）
        │
        │ 提供 raw URL 访问 data/bangumi.jsonl
        ↓
[3] Excel 加载项 (本项目)  ── WPS 插件
        ├─ 📥 数据同步：远程仓库 → Excel（读取 JSONL 写入工作表）
        ├─ 📤 上传同步：Excel → Bangumi API（上传观看状态、评分等）
        └─ 📥 收藏回写：Bangumi API → Excel（获取用户收藏列表标记到工作表）
```

| 上游                          | 提供内容                                                | 访问方式                                                                                         |
| ----------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `Bangumi-Archive-Anime-Excel` | `data/bangumi.jsonl`（紧凑 JSONL，~15.80 MB，30502 条） | `https://raw.githubusercontent.com/awujiana/Bangumi-Archive-Anime-Excel/main/data/bangumi.jsonl` |

**插件端默认配置**：

| 配置项 | 值                            |
| ------ | ----------------------------- |
| 同步源 | GitHub                        |
| owner  | `awujiana`                    |
| repo   | `Bangumi-Archive-Anime-Excel` |
| branch | `main`                        |
| path   | `data/bangumi.jsonl`          |

**JSONL 字段集概要**（25 个字段，3 类，详见 [docs/github-data-distribution.md](./docs/github-data-distribution.md)）：

| 类别             | 字段数 | 字段列表                                                                                                                                                                                           |
| ---------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 基础字段         | 3      | `sid`、`name`、`updatedAt`（`YYYY-MM-DD` 仅日期）                                                                                                                                                  |
| dump 顶层扩展    | 3      | `date`、`meta_tags`、`nsfw`                                                                                                                                                                        |
| infobox 解析扩展 | 19     | `话数`、`播放结束`、`动画制作公司`、`片长`、`制片国家`、`语言`、`类型`、`导演`、`音乐`、`人物设定`、`机械设定`、`原作`、`脚本`、`分镜`、`演出`、`原案`、`系列构成`、`在线播放平台`、`关联的动漫ID` |

不输出字段（已移除以减少冗余）：`url`（从 `sid` 构造）、`type`（dump 恒为 2，与 BGM 插件观看状态语义无关）、`tags`（与 `meta_tags` 冗余）、`episode`（dump 恒为 0，用 `话数` 替代）、`platform`、`score`、`comment`。

详细跨项目链路见上级目录 [../../README.md](../../README.md)。

依赖方向严格自上而下；`index.ts` 作为统一 barrel 导出入口，降低模块间耦合。

### 4.2 同步引擎（sync/）

本项目包含 **三个方向完全不同的同步操作**，互不冲突：

| 同步操作        | 方向                | Ribbon 按钮                     | 面板区域                    | 说明                                                                                                     |
| --------------- | ------------------- | ------------------------------- | --------------------------- | -------------------------------------------------------------------------------------------------------- |
| **📤 上传同步** | Excel → Bangumi API | `btnSyncBangumi`「上传同步」    | 快捷操作                    | 将 Excel 中的观看状态、评分、标签、评论等上传到 Bangumi 服务端                                           |
| **📥 数据同步** | 远程仓库 → Excel    | `btnSyncFromGithub`「数据同步」 | 数据同步（远程仓库 → 本地） | 从 GitHub/GitLab/Gitee/Gist/本地文件下载 Bangumi 资料数据（名称、标签、集数等），按 SID 增量合并到工作表 |
| **📥 收藏回写** | Bangumi API → Excel | —                               | 快捷操作 / 同步记录         | 从 Bangumi 获取用户收藏列表（collect/wish/do），标记到 Excel 工作表                                      |

#### 4.2.1 📤 上传同步（Excel → Bangumi API）

主入口：`ts/sync/exceltobangumi.ts` 的 `SyncToBangumiAsync`

```
SyncToBangumiAsync (主协调)
  ├─ prepareSyncTasks
  │   ├─ fetchVisibleRowsForSync    [数据获取]
  │   ├─ buildFingerprintMap         [数据获取]
  │   └─ processRowToSyncTask ×N     [业务处理]
  ├─ executeBatchSync                [业务处理]
  └─ finalizeSyncResults
      ├─ applySyncSuccessResults     [UI更新]
      ├─ applySyncFailResults        [UI更新]
      └─ handleStoppedRemainingTasks [UI更新]
```

关键能力：

- 防重入（`enterRunningState`/`exitRunningState` 状态机）
- 暂停/恢复/停止（`shouldStop`/`isPaused`/`waitForResume` 50ms 轮询）
- 增量同步（指纹缓存 `fingerprintMap`，跳过未变更行）
- 进度弹窗（`showSyncProgressDialog` + `updateSyncProgressDialog` + `completeSyncProgressDialog`）
- 冲突检测（`detectConflicts`）
- 同步记录工作表（`syncRecord.ts`）

#### 4.2.2 📥 数据同步（远程仓库 → Excel）

主入口：`ts/sync/githubSync.ts` 的 `syncFromGithub`

```
插件 ──① 读取──▶ data/bangumi.jsonl (raw URL)
                   │
                   │ ② 逐行解析 JSONL（githubSyncDiff.ts computeDiff）
                   ▼
            ③ 按 SID 比对本地 Excel 行
                   │
                   │ ④ 应用冲突解决（applyConflictResolutions）
                   ▼
            ⑤ 增量写入（applyDiffToSheet）
```

5 种同步策略：

| 策略              | 说明                                 |
| ----------------- | ------------------------------------ |
| `add-update`      | 新增+更新，不删除（默认，保守）      |
| `add-only`        | 仅新增本地不存在的 SID，不更新已有行 |
| `update-only`     | 仅更新本地已存在的 SID，不新增行     |
| `mirror`          | 镜像同步（新增+更新+删除本地多余行） |
| `force-overwrite` | 强制覆盖（用远程值覆盖本地，含空值） |

#### 4.2.3 同步源抽象

`SyncSource` 接口 + `syncSourceRegistry` 注册表，支持 5 种同步源：

| 同步源   | 实现文件           | 说明                 |
| -------- | ------------------ | -------------------- |
| GitHub   | `githubSync.ts`    | 当前默认，读 raw URL |
| GitLab   | `gitlabSync.ts`    | 读 GitLab raw URL    |
| Gitee    | `giteeSync.ts`     | 读 Gitee raw URL     |
| Gist     | `gistSync.ts`      | 读 GitHub Gist API   |
| 本地文件 | `localFileSync.ts` | 读本地 JSONL 文件    |

#### 4.2.4 📥 收藏回写（Bangumi API → Excel）

主入口：`ts/ui/handlers/index.ts` 的 `syncCollectionFromBgm` action

```
Bangumi API ──① 请求──▶ 用户收藏列表（collect/wish/do）
               │
               │ ② 逐条解析收藏条目
               ▼
        ③ 按 SID 匹配 Excel 行
               │
               │ ④ 标记收藏状态到工作表
               ▼
        ⑤ 更新同步记录
```

与上传同步的区别：上传同步是 Excel→Bangumi（写入用户数据到服务端），收藏回写是 Bangumi→Excel（读取服务端数据到本地），方向相反。

### 4.3 UI 层（ui/）

### 6.1 OAuth 2.0 授权流程

详细流程见 [文档/How-to-Auth.md](./文档/How-to-Auth.md)。摘要：

1. 引导用户访问 `GET https://bgm.tv/oauth/authorize?client_id=...&response_type=code&redirect_uri=...`
2. Bangumi 回调返回 `code`（60 秒有效）
3. 后端 `POST https://bgm.tv/oauth/access_token` 换取 `access_token` + `refresh_token`（7 天有效）
4. 携带 `Authorization: Bearer {access_token}` 调用 API
5. 用 `refresh_token` 续期

### 6.2 Token 安全

- 存储：XOR 加密后写入 PluginStorage（`core/crypto.ts`）
- 传输：仅 Authorization Header，不通过 query string
- 校验：`verifyToken`（`sync/scraping.ts`）
- 清理：`clearBgToken`（`tools/util.ts`）

> ⚠️ 审查 B6-STORAGE-P1：XOR 加密已废弃降级，建议升级为浏览器原生 `SubtleCrypto`（待修复）

## 十一、WPS Ribbon 图标加载经验总结

### 11.1 问题现象

Ribbon 工具栏按钮显示为问号占位图，点击无反应。图标源文件（`images/` 目录下的 SVG 文件）存在且内容正确。

### 11.2 根因分析

WPS Ribbon 的图标加载机制存在以下关键特性：

| 特性             | 说明                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------- |
| **路径解析基准** | WPS 从加载项**安装目录**解析图标路径，而非项目根目录或 HTML 文件所在目录               |
| **图标缓存机制** | Ribbon 图标会被 WPS 缓存，早期占位返回空值会导致 WPS 缓存空结果                        |
| **回调函数要求** | `GetImage`/`GetBangumiImage` 回调必须返回**相对路径字符串**（如 `'images/panel.svg'`） |

### 11.3 尝试过的方案及结果

| 方案            | 尝试方式                                          | 结果    | 原因                                    |
| --------------- | ------------------------------------------------- | ------- | --------------------------------------- |
| **相对路径**    | `return 'images/panel.svg'`                       | ✅ 成功 | WPS 从加载项目录解析，自动加载 SVG 文件 |
| HTTP 绝对 URL   | `return 'http://127.0.0.1:3889/images/panel.svg'` | ❌ 失败 | WPS Ribbon 上下文不支持 HTTP 协议加载   |
| base64 data URI | `return 'data:image/svg+xml;base64,...'`          | ❌ 失败 | WPS Ribbon 不支持 data URI 作为图标源   |
| SVG 内容字符串  | `return '<svg>...</svg>'`                         | ❌ 失败 | WPS Ribbon 不支持直接返回 SVG 标记      |
| 空字符串占位    | `return ''`                                       | ❌ 失败 | WPS 缓存空结果，导致图标永久显示为问号  |

### 11.4 关键时序问题

Ribbon 图标加载涉及两个阶段的函数调用：

```
WPS 加载 Ribbon
    │
    ├─ ① 早期占位阶段（index.html 内联 <script>）
    │   └─ GetBangumiImage() 返回占位路径
    │
    ├─ ② 真实模块就绪阶段（ts/ribbon.ts 编译后加载）
    │   ├─ 替换 window._GetBangumiImageReal
    │   └─ 调用 ribbonUI.Invalidate() 刷新缓存
    │
    └─ ③ WPS 重新请求图标 → 使用真实实现
```

**关键约束**：

- 早期占位函数必须返回**有效相对路径**，不能返回空字符串
- 真实模块加载后必须调用 `ribbonUI.Invalidate()` 强制刷新缓存
- 早期占位函数与真实实现的返回格式必须一致（均为相对路径）

### 11.5 规范代码

```typescript
// index.html 早期占位
window.GetBangumiImage = function (control) {
  if (_ribbonReady && typeof window._GetBangumiImageReal === 'function') {
    return window._GetBangumiImageReal(control)
  }
  // 必须返回有效相对路径，不可返回空字符串
  var icons = {
    btnShowPanel: 'images/panel.svg',
    btnSyncBangumi: 'images/sync.svg',
    // ...
  }
  return icons[control && control.Id] || 'images/newFromTemp.svg'
}

// ts/ribbon.ts 真实实现
const ICON_PATHS: Record<string, string> = {
  btnShowPanel: 'images/panel.svg',
  btnSyncBangumi: 'images/sync.svg',
  // ...
}

export function GetBangumiImage(control: { Id: string }): string {
  return ICON_PATHS[control.Id] || 'images/newFromTemp.svg'
}

// 真实模块加载后刷新
window._GetBangumiImageReal = GetBangumiImage
window._bgmRibbonReady = true
ribbonUI.Invalidate() // 强制刷新 WPS 图标缓存
```

### 11.6 经验教训

1. **WPS Ribbon 的图标加载机制与浏览器不同**，不能假设 HTTP URL 或 data URI 可用。最可靠的方式是返回相对路径字符串，让 WPS 从加载项目录解析。
2. **早期占位函数不能返回空值**，WPS 会缓存空结果导致永久显示问号。即使真实模块尚未就绪，也应返回一个有效的默认图标路径。
3. **模块加载时序很重要**，真实模块替换占位函数后，必须调用 `ribbonUI.Invalidate()` 通知 WPS 刷新缓存。
4. **与成功案例保持一致**，优先参考 WPS 官方示例或已知可用的简单实现，而非猜测复杂方案。

### 11.7 相关文件

| 文件                       | 角色                                                                   |

| `ribbon.xml`               | Ribbon 面板配置，定义按钮 ID 和回调函数名                              |

| `ts/ribbon.ts`             | 真实 `GetBangumiImage` 实现                                            |

## 十二、Ribbon ↔ Taskpane 复选框双向同步机制

### 12.1 三个同步开关

Ribbon 面板和 Taskpane 面板均存在以下 3 个复选框/下拉框，需实现实时双向同步：

| 配置 key                 | Ribbon ID             | Taskpane ID                 | 含义                   |
| ------------------------ | --------------------- | --------------------------- | ---------------------- |
| `bgm_incremental_sync`   | `chkIncrementalSync`  | `chkIncremental`            | 仅同步变更（增量同步） |
| `bgm_skip_conflicts`     | `chkSkipConflicts`    | `conflictStrategy` (select) | 跳过冲突 / Excel 覆盖  |
| `bgm_enable_sync_record` | `chkEnableSyncRecord` | `chkEnableSyncRecord`       | 启用同步记录           |

### 12.2 运行时上下文隔离

- **Ribbon 上下文**：运行在 `index.html` 顶层窗口（用户不可见），WPS Ribbon 的 getPressed/onAction 回调在此执行。
- **Taskpane 上下文**：运行在 `taskpane.html` 窗口（用户可见的侧边栏），checkbox/select 的 DOM 操作在此执行。
- 两个上下文共享同一个 `PluginStorage`（持久化配置），但 JS 变量、eventBus、DOM 完全隔离。**同页面内 eventBus 不能跨上下文通知**。

### 12.3 双向同步链路

```
┌────────────────────────────────────────────────────────────────────┐
│                     用户操作任一界面                                │
│                                                                    │
│  ┌──────────────┐              ┌──────────────┐                    │
│  │   Ribbon     │              │  Taskpane    │                    │
│  │  checkbox    │              │  checkbox    │                    │
│  └──────┬───────┘              └──────┬───────┘                    │
│         │ ① onAction                   │ ① change event            │
│         ▼                              ▼                           │
│  ┌──────────────────────────────────────────────────┐              │
│  │  setConfig(key, value)  ← config.ts              │              │
│  │  ① PluginStorage.setItem() 持久化                │              │
│  │  ② eventBus.emit(CONFIG_UPDATED) 同页面内通知    │              │
│  │  ③ window.postMessage(BGM:configUpdated) 跨页面  │◄── 新增广播  │
│  └──────┬───────────────────────────┬───────────────┘              │
│         │ 跨文档消息                │ 跨文档消息                    │
│         ▼                           ▼                               │
│  ┌─────────────────┐      ┌─────────────────────┐                  │
│  │ Ribbon 消息监听 │      │ Taskpane 消息监听    │                  │

```

### 12.4 关键代码点

| 角色                         | 文件                             | 函数/位置                                                                                   | 职责                                                                                     |
| ---------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| **配置变更入口**             | `ts/tools/config.ts`             | `setConfig()`                                                                               | 存储配置 + eventBus + **postMessage 广播**（修复前缺失 Taskpane→Ribbon 通知）            |
| **Ribbon 回调**              | `ts/ribbon.ts`                   | `GetIncrementalSyncPressed` 等                                                              | WPS 查询状态时从 `getIncrementalSync()` 读取 PluginStorage                               |

### 12.5 2026-08 修复的历史问题

| 缺陷                                                                    | 影响                                                               | 修复                                                                                                   |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| `setConfig()` 不发 postMessage                                          | Taskpane 勾选 → Ribbon checkbox 状态不刷新（需重新加载插件才同步） | 在 `setConfig` 中加入 `window.parent/top/window.postMessage(BGM:configUpdated)` 三重广播（修复时加入） |
| Ribbon 监听器只处理 incremental / skip_conflicts，缺 enable_sync_record | 启用同步记录 Taskpane→Ribbon 方向不刷新                            | 在 `controlIdMap` 中补齐 `bgm_enable_sync_record → chkEnableSyncRecord`                                |
| Taskpane `handleConfigUpdatedEvent` 缺 enable_sync_record 分支          | Ribbon 勾/取消同步记录 → Taskpane checkbox 不更新                  | 新增 `bgm_enable_sync_record` → `tryUpdateEnableSyncRecordUI()` 分支                                   |
| `setupButtonListeners()` 只注册 change 监听器、不加载初始值             | Taskpane 首次打开时 sync_record checkbox 与 PluginStorage 不一致   | 在注册监听器前先从 `getSyncRecordEnabled()` 读取并设置 `checked`                                       |

### 12.6 验证方法

1. 打开 Ribbon 和 Taskpane 两个界面。
2. 勾选 Ribbon 侧「仅同步变更」→ Taskpane 侧 checkbox 应立即同步。
3. 取消 Taskpane 侧「仅同步变更」→ Ribbon 侧 checkbox 应立即同步。
4. 同样对「跳过冲突」（Ribbon checkbox ↔ Taskpane select）和「启用同步记录」执行相同测试。
5. 打开调试面板 Console Tab 应看到：`[config] 已广播 BGM:configUpdated`、`[ribbon-message] 已 InvalidateControl`、`[handlers] 已更新 xxx 复选框` 等日志。
