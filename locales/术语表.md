## 二、OpenCC 会翻错的词（必须人工覆盖）

这几条是实测 `s2twp` 出来的**错译**，生成脚本里用 `TERM_FIX` 逐条替换：

| 简体        | OpenCC 输出（错） | 正确        | 原因                                                                            |
| ----------- | ----------------- | ----------- | ------------------------------------------------------------------------------- |
| 账号 / 账户 | 賬號 / 賬戶       | 帳號 / 帳戶 | 台湾一律用「帳」                                                                |
| 当前        | 當前              | 目前        | 「當前」是大陆用法                                                              |
| 镜像        | 映象              | 鏡像        | 「映象」是 image 的音译，mirror 用「鏡像」                                      |
| 记事本里    | 記事本里          | 記事本裡    | 「里」繁简同形，OpenCC 不敢动；方位词台湾写「裡」                               |
| 只（副词）  | 隻                | 只          | 「隻」是动物量词。OpenCC 见「只」一律转「隻」，实测把「只改写」错转成「隻改寫」 |

## 三、`<code>` 里的东西一律不翻

分片字段名（`话数` / `导演` / `音乐` / `动画制作公司` / `系列构成`）、文件名
（`data/anime.manifest.json`）、URL、JSON 样本、`bgm_*` 存储键 —— 这些是**字面量**，
用户会照着写进表格或代码。翻成繁体就成了「另一个字段名」，对不上。

生成脚本对 `<code>…</code>` 做**先挖掉、转换完再放回**，所以语言包里这些片段
保持简体原样。校对时看到 `<code>` 里是简体，**是正确行为，不要改**。

## 四、标点

- 正文用全角 `，。：；！？`，与简体一致（繁简同形，无需转换）。
- 引号统一 `「」`（书名号、强调都走它）；`"…"` 只在引用原始 JSON / 文件名时出现。
- 括号用全角 `（）`；括号内是纯英文时保留半角 `( )`。

## 五、不翻译的内容

| 内容                                                            | 原因                                   |
| --------------------------------------------------------------- | -------------------------------------- |
| 语言按钮上的「简体中文 / 繁體中文 / English」                   | 各语言显示自己的母语名，这是 i18n 惯例 |
| `Bangumi`、`WPS`、`GitHub`、`Token`、`SID`、`URL`、`CSV`、`TXT` | 专有名词 / 缩写                        |
| 日志正文                                                        | 面向开发者排查，不进语言包             |

## 六、当前覆盖率

| 语言    | key 数 | 覆盖率 | 说明                                                        |
| ------- | ------ | ------ | ----------------------------------------------------------- |
| `zh-CN` | 1508   | 100%   | 源语言，**由 `ui/*.html` 的 `data-i18n*` 自动提取**，不手写 |
| `zh-TW` | 1508   | 100%   | 本表 §一~§五 校对完毕；`<code>` 内保持简体属正常            |
| `en`    | 1508   | 100%   | P3 完成（2026-11-01）；规范见 §七                           |

> 数字随 P5 批次增长：407（P2/P3 基线）→ 576（赞赏/清理/高亮页）→ 797（富化页）→ 923（条件格式页静态标记）→ 1167（条件格式页 toast 与拼接片段）→ 1236（顶栏 / 既有规则卡片 / 规则库列表）→ 1336（弹窗与右键菜单）→ 1400（共享组件）→ 1381（折叠按钮 aria 收成 1 个 key，净减 19）→ 1405（handlers 小文件组）→ 1508（handlers 中文件组 + 快捷键动作表）。
> 口径见 `locales/index.js` 的 `keyCount`，以它为准，别手抄。

> 覆盖率口径：`该语言有的 key 数 / zh-CN 的 key 数`。缺的 key 运行时**回退到简体**，
> 不会露 key（`t()` 有源语言兜底）。
>
> **门禁要求 100%**（`check:i18n` 规则 ⑧）：加 key 时三份语言包必须一起补，缺一个就红。
> 之所以不用 95% 这种阈值——阈值以下的缺口照样是「用户看到中文」，而 95% 的线还会让
> 「加了 1 个 key 忘了翻」稳稳过关。

### 7.2 这些中文是**故意留着的**，别当漏译改掉

| 位置                                                                                     | 为什么                                    |
| ---------------------------------------------------------------------------------------- | ----------------------------------------- |
| `<code>…</code>` 里的字段名（`话数` / `导演` / `系列构成`）、文件名、URL、`bgm_*` 存储键 | 字面量，用户照着写进表格 / 代码           |
| `syncPanel.help.td*`（列名一列）                                                         | 模板是中文表头，写英文用户就对不上列了    |
| `syncPanel.remote.mirrorNote` 里的 `别名` / `标签/分级` / `制作公司`                     | 同上，是列名                              |
| `syncPanel.records.syncHint` 里的「同步记录」                                            | `SYNC_RECORD_SHEET_NAME` 硬编码的真实表名 |
| `settings.enrichPreview.noisePlaceholder` / `noiseHint` 里的噪声词                       | 数据里真实出现的噪声字符串                |

### 7.3 标点与引号

- 正文用半角英文标点，句末句号 `.`，逗号 `,`。
- 引号用**弯引号** `“ ”`，不用 `" "` —— 一来排版正确，二来 JSON 里不必转义。
- 中文界面里的 `「」` 在英文包里换成 `“ ”`。

### 7.4 长度

英文比中文长 30–50%。实测（`node scripts/audit-layout.mjs --locale en`）：

- `settings.html` 在 400 / 500px 下**无异常**；
- `sync-panel.html` 的核心操作按钮在窄窗格折成两行（`👆 Sync Selected Rows` /
  `🎯 Retry Failed Rows` / `📥 Collection Download`）。网格是 `minmax(132px, 1fr)`，
  同一行按钮**等高对齐**，观感可接受，因此没有为它们造短版 key。
  若以后要改：宁可调 `.command-actions` 的列宽，也别加 `.short` 变体——
  按宽度选 key 需要在 JS 里监听 resize，为一个折行不值当。

> `--locale` 会把语言包内联进探针再量，因为 Chrome 在 `file://` 下动态 `import()`
> 本地模块会永远挂住（`--allow-file-access-from-files` 无效，`--disable-web-security`
> 在真实页面上同样卡死）。见 `scripts/audit-layout.mjs` 的 `buildLocaleProbe()`。
