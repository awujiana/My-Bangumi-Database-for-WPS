当 Excel 条目与 Bangumi 收藏状态不一致时，自动按所选策略处理。

🗄️ 数据同步（远程仓库 → 本地）

从远程仓库下载 Bangumi 资料数据（名称、标签、集数等），按 SID 增量合并到当前工作表（新增+更新，不删除）。
与「📤 上传同步」方向相反：上传同步是 Excel→Bangumi，数据同步是 远程仓库→Excel。

不勾选任何分片 = 按当前表头自动选择，只下载会用到的分片（例如表里没有 长文本列就不会下载 infobox 片）。勾选后以勾选结果为准；基础分片不可取消， 因为 SID / 名称 / 更新时间都只在它里面。
数据仓库的清单文件是 data/anime.manifest.json，分片同目录。

必须指向分片清单（anime.manifest.json），分片文件需与其同目录； 复用 #githubPath 字段存储路径（与远程源互斥）。

通过 https://api.github.com/gists/{gistId} 获取，未认证限流 60 次/小时。

⚠️ 镜像同步说明：该策略并非完全镜像远程仓库。若要完全与远程一致，需先删除本地全部数据后再同步。
• 新增条目（writeAll=true）：正常写入所有字段
• 更新条目：名称追加到「别名」列、标签追加到「标签/分级」列（以 | 分隔），其他字段直接覆盖
• 制作公司/动画制作公司：远程「动画制作公司」字段会同时更新本地「制作公司」和「动画制作公司」两列

分片清单：data/anime.manifest.json 列出 6 个分片（base / meta / relations / stats / summary / infobox），插件按你的表头只下载需要的片
分片格式：每片是 gzip 压缩的 JSONL，第 1 行是表头（字段名数组），其后每行是与表头等长的值数组；各片都含 subjectId、行序一致，插件按行号拼接
["sid","name","updatedAt","date","meta_tags","nsfw","话数","导演","动画制作公司","系列构成"]
["8","Code Geass R2","2026-09-08","2008-04-06",["机战","TV","日本"],false,"25","谷口悟朗","サンライズ","大河内一楼"]
基础字段：subjectId（必填）、name、updatedAt（YYYY-MM-DD）
扩展字段：date、meta_tags、nsfw、话数、导演、音乐、动画制作公司、系列构成 等

📘 操作流程详解

1️⃣ Token 设置
• 点击「设置/修改」按钮，按引导创建 Bangumi OAuth Token
• Token 有效期通常为 30 天，过期后需重新获取
• 设置后自动显示用户头像和信息

2️⃣ 数据同步（远程仓库 → 本地 Excel）
• 配置远程仓库地址（GitHub/GitLab/Gitee/Gist/本地文件）
• 选择同步策略：新增+更新 / 仅新增 / 仅更新 / 镜像同步 / 强制覆盖
• 可选：启用时间筛选（按开播日期过滤）
• 点击「立即同步」开始下载并合并数据

3️⃣ 上传同步（本地 Excel → Bangumi）
• 确保每行包含 Bangumi_URL 列
• 选择行范围，设置冲突处理策略
• 点击「📤 上传同步」执行

4️⃣ 收藏下载（Bangumi → 本地 Excel）
• 选择收藏类型：已看 / 想看 / 在看
• 点击「📥 收藏下载」标记到 Excel

⚠️ 注意事项
• 镜像同步不是完全镜像！要完全与远程一致需先删除本地数据
• 批量操作建议先在副本上测试确认无误后再在正式数据上执行
